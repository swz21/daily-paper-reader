## 摘要
姿态驱动的人体动画从单张参考图像和驱动姿态流合成目标人物的视频。实时生成对于直播、远程呈现和虚拟化身等交互式应用至关重要，然而基于扩散的系统每个片段需要数分钟到数小时，妨碍了响应式交互。我们提出了LiveAnimate，据我们所知，这是首个将实时流式与十亿参数规模的稳定长时生成相结合的动画系统，构建于一个140亿参数的视频扩散Transformer（DiT）之上。两阶段训练流程首先通过参考锚定教师强制适配（Reference-Anchored Teacher-Forcing Adaptation）将预训练的双向DiT改造为块因果自回归生成器，然后通过分块自强制蒸馏（Block-wise Self-Forcing Distillation）将采样预算减少到三步。为了在长时间流中保持外观一致性，我们引入了姿态检索汇聚注意力（Pose-Retrieval Sink Attention, PR-Sink），一种有界KV缓存机制，结合了一个静态汇聚（Static Sink）——永久锚定第一个生成的块，一个动态汇聚（Dynamic Sink）——保存姿态检索到的历史块，以及一个三槽滚动窗口（three-slot Rolling Window）。当姿态重现时，PR-Sink恢复相关的外观上下文，而无需保留整个序列，因此内存和每块延迟与流持续时间无关。结合Ulysses序列并行和算子融合，这些设计使得在两块NVIDIA H100 GPU上实现19.63 FPS的流式推理。在一个三分钟的基准测试中，LiveAnimate从最初的30秒到最后一分钟几乎保持恒定的感知质量和身份一致性（IQA 4.047对4.026），而先前系统则严重退化或需要数小时的离线计算才能完成相同的滚动输出。这些结果为交互式全身动画在质量、延迟和时长方面确立了新的操作点。

## Abstract
Pose-driven human animation synthesizes a video of a target person from a single reference image and a driving pose stream. Real-time generation is essential for interactive applications such as live streaming, telepresence, and virtual avatars, yet diffusion-based systems require minutes to hours per clip, precluding responsive interaction. We present LiveAnimate, to our knowledge the first animation system to combine real-time streaming with stable long-form generation at billion scale, built on a 14B-parameter video Diffusion Transformer (DiT). A two-stage training pipeline first adapts a pretrained bidirectional DiT into a block-causal autoregressive generator through Reference-Anchored Teacher-Forcing Adaptation, and then reduces the sampling budget to three steps through Block-wise Self-Forcing Distillation. To preserve appearance over extended streams, we introduce Pose-Retrieval Sink Attention (PR-Sink), a bounded KV-cache mechanism combining a Static Sink that permanently anchors the first generated block, a Dynamic Sink that holds a pose-retrieved historical block, and a three-slot Rolling Window. When a pose recurs, PR-Sink restores the relevant appearance context without retaining the entire sequence, so memory and per-block latency remain constant regardless of stream duration. Together with Ulysses sequence parallelism and operator fusion, these designs enable 19.63\,FPS streaming inference on two NVIDIA H100 GPUs. On a three-minute benchmark, LiveAnimate maintains nearly constant perceptual quality and identity from the first 30 seconds to the final minute (IQA 4.047 vs.\ 4.026), while prior systems degrade substantially or require hours of offline computation for the same rollout. These results establish a new operating point in quality, latency, and duration for interactive full-body animation.

# LiveAnimate：实时稳定的长时流式人体动画

## 1. 核心问题与整体含义

- **研究背景**：姿态驱动（pose-driven）人体动画的目标是从单张参考图像和一段驱动姿态流中合成目标人物的视频，广泛应用于虚拟试穿、数字人、直播和远程呈现等场景。主流方案基于视频扩散模型，能做到高保真，但推理成本极高——生成一个片段通常需要数分钟到数小时，无法满足实时交互需求。
- **核心矛盾**：已有方法大多离线生成固定长度片段，不支持开放式的姿态流输入；即便能做到分钟级生成（如 EverAnimate），仍需要大量去噪步骤，距离实时甚远。同时，长时自回归生成容易累积误差，导致身份与外观漂移。
- **本文贡献**：提出 **LiveAnimate**，据称是首个在 **14B 参数规模**下同时实现“实时流式生成 + 稳定长时生成”的全身体动画系统，在两块 H100 GPU 上达到约 20 FPS 的流式推理速度，且三分钟长序列内质量几乎不衰减。

## 2. 方法论

### 2.1 总体框架
- 给定参考图像 `I_ref` 和逐步到达的驱动姿态序列 `{P_t}`，系统按“块”（block）自回归生成视频；每个块包含 3 个潜变量帧（对应 12 个 RGB 帧），经 3 步去噪后写入干净 KV 缓存。
- 整体由三部分组成：两阶段训练流程、PR-Sink 有界 KV 缓存机制、系统级并行优化。

### 2.2 Stage 1：参考锚定教师强制适配
- 将预训练的双向 DiT 改造成块因果（block-causal）自回归生成器。
- 训练时将每个块的条件历史设为**真实干净历史块 `z_GT_<b`**，避免第一阶段的错误累积；自生成历史只在第二阶段引入。
- 核心设计是 **Ref Sink**：参考图像潜变量在干净时间步 `t=0` 前向编码后，其 KV 状态作为全局条件缓存，对所有后续块可见，起到类似 LLM attention sink 的永久外观锚定作用。
- 块 b 的注意力公式为：
  `Attn(Q_b, K, V) = softmax( Q_b [K_ref; K_<b]^T / sqrt(d) ) [V_ref; V_<b]`
- 推理或第二阶段自强迫 rollout 中，去噪得到的块 `z_hat_b^0` 会通过 Clean KV Update 做一次 `t=0` 的额外前向，写入历史缓存：
  `KV cache ← KV cache ∪ Forward(z_hat_b^0, t=0, C)`

### 2.3 Stage 2：块级自强迫蒸馏（BS-DMD）
- 目标：将每块所需的 50 步去噪降至 3 步。
- 两遍“块级重放”流程：
  - **Pass 1（无梯度自强迫 rollout）**：学生模型用自身预测作为历史条件，生成完整轨迹 `(z̄_1, …, z̄_N)`，不保留反向传播图。
  - **Pass 2（逐块 DMD 优化）**：对块位置 T=1,…,N 逐个重放。历史上下文来自 Pass 1 并 `stop-gradient`，只对当前块 `z_θ^T` 计算梯度；把重放块插回 detach 的轨迹后，计算分布匹配蒸馏损失 `L_T = L_DMD( z̃^(T); C )`。
- 每处理一块就释放激活图，因此训练峰值内存可控，14B 模型可在**单个 8×H100 80GB 节点**上完成蒸馏；训练采用 LoRA（rank=128）以进一步降低参数量。

### 2.4 姿态检索汇聚注意力（PR-Sink）
- 解决“有界缓存导致长程外观信息丢失”的问题，组合两类持久区域：
  - **Static Sink**：永久保留第一个生成块的 KV，提供时间不变的外观锚点；
  - **Dynamic Sink**：从紧凑记忆库中检索与当前姿态最相似的历史块，恢复“姿态相关的局部外观证据”；
  - 外加 **三槽 Rolling Window**（两个最近历史块 + 当前块）。
- **置信度感知的全身姿态指纹**：用 ViTPose 提取 133 个关键点，保留身体 20 点 + 双手各 21 点，去掉面部轮廓点；将块内 3 帧的有序关键点拼接并 L2 归一化，得到 558 维指纹 `φ_b`，用于姿态相似度计算。
- **记忆库更新（保多样性）**：库容量 M=5。新块到来时测试所有替换方案，选择使库内平均两两余弦相似度最低的方案；只有能降低当前库平均相似度时才替换。更新限制在前 20 个块，之后复用选出的代表块。
- **姿态最近邻检索**：生成当前块前，检索与当前指纹余弦相似度最高的历史块（排除 b−1，因为其已在滚动窗口中），其 KV 写入 Dynamic Sink。
- **位置一致的 KV 复用**：缓存的是 RoPE 之前的原始 K、V；检索后按当前缓存布局的指定位置重新旋转位置编码，避免历史块时间戳错位。

### 2.5 系统优化
- **Ulysses 序列并行**：各 GPU 先计算局部 token 的 Q/K/V，再通过 all-to-all 转为 head-parallel，让每个 GPU 计算完整序列注意力的部分头；FFN 仍按局部 token 并行，KV 缓存按 GPU head 分片独立维护。
- **torch.compile**：所有 DiT 块用 `max-autotune-no-cudagraphs` 预编译，适配 480×480、672×384、384×672 三种分辨率桶。
- 效果：单卡 12.41 FPS，双卡 19.63 FPS（并行效率 79.1%），四卡 22.13 FPS（效率降至 44.6%）。

## 6. 主要结论

- 两阶段训练可将 14B 双向 DiT 转化为三步采样的块因果生成器，且蒸馏训练在单节点可行。
- PR-Sink 用“Static Sink 保全局外观 + Dynamic Sink 恢复重复姿态的局部上下文 + 有界滚动窗口”的方式，在固定内存下维持长时一致性。
- 三分钟基准中，LiveAnimate 的 IQA 从 4.047 仅微降至 4.026，ASE 稳定在 2.823→2.824，DINO-S 从 0.833 降至 0.818，几乎无累积退化；对比方法（如 One-to-All）的 IQA 从 3.402 降至 1.786、DINO-S 跌至 0.328。
- 在两块 H100 上达到 19.63 FPS，单块 12 帧生成延迟约 0.611 秒，且延迟和内存不随流长度增长。
- 作者称这是首个在十亿参数规模下同时具备实时流式与稳定长时生成能力的人体动画系统，为交互式全身动画在质量、延迟、时长三者之间打开了新的操作点。

## 7. 优点

- **方法创新性强**：将 LLM 中的 attention sink 思想引入条件视频生成，并进一步发展为“静态 + 动态双 sink”结构；姿态检索恢复历史上下文的设计直观且有效。
- **训练策略实用**：Block-wise Self-Forcing Distillation 通过“无梯度 rollout + 逐块重放”避免对完整自回归轨迹反传，解决了 14B 模型蒸馏的显存瓶颈。
- **推理性能突出**：在保持高感知质量和身份一致性的前提下达到实时帧率，且显存/延迟复杂度与流时长无关，工程实现上有很强的实用性。
- **实验设计严谨**：三分钟基准特意引入姿态重复（forward-reverse-forward），直接针对“姿态重现时外观保持”这一核心难点；指标选择避免像素对齐对合理运动变化的误伤。
- **透明性较好**：给出推理耗时分解、并行扩展效率，让读者能清楚判断性能瓶颈与扩展性。

## 8. 不足与局限

- **分辨率与画质受限**：当前仅支持 480×480（及 672×384、384×672）分辨率，三步采样限制了细节和视觉保真度，作者也承认这一点。
- **场景能力受限**：不支持多人场景，也无法处理剧烈相机运动；姿态库更新被限制在前 20 个块，若后续出现完全新颖的姿态，Dynamic Sink 只能依赖已有代表块，信息覆盖存在上限。
- **训练数据与算力未充分披露**：未给出训练墙钟时间，也未报告 LoRA 之外可训练参数量、显存峰值等关键训练成本细节。
- **实时性口径待商榷**：延迟统计排除 VAE 编解码和条件处理，若计入端到端延迟，真实帧率可能低于 19.63 FPS；作者表示这些模块可流水线重叠，但论文没有给出完整的端到端测量。
- **对比公平性风险**：基线多为离线或定长生成模型，长视频扩展方式并非其原生能力；实时性对比在本质上有利于本方法，尽管作者采用了官方或统一扩展协议来尽量规避偏差。
- **评估局限**：帧级指标（ASE/IQA）无法完全捕捉时间一致性，V-MAE 是特征距离而非显式的时序稳定性度量；主观用户研究（如偏好度、身份保持评分）缺失。
- **未解决根本性问题**：Clean KV Update 只消除噪声水平不匹配，不会移除生成块中的已有错误；当自回归误差真正发生漂移时，PR-Sink 也无法完全修复，只是缓解。
